# ShiningPass — 建築インテリア プラットフォーム

[English](ShiningPass.md) · [한국어](ShiningPass_ko.md) · [日本語](ShiningPass_ja.md)

---

## ひとことで

**Python + AWS** でバックエンドとフロント（公式サイト）を作り、  
認証された顧客だけが入る **UE5 クライアント** までつないだ建築インテリア システムです。

Web で顧客を集め・管理し、  
クライアント内では空間の **素材・家具** を差し替えながら設計を確認します。

**公式サイト:** [https://shiningpass.com](https://shiningpass.com)

---

## プロジェクトの理由

建築・インテリアの営業や検討では、  
「この仕上げに変えたら空間はどう見えるか」を  
図面だけではすぐ見せにくいです。

ShiningPass はそのギャップを埋めるため、

1. **Web** でブランド・集客・アカウント  
2. **UE5 クライアント** で実写に近い空間体験と素材変更  

を一本につないだ構成です。

---

## 全体構成

```text
公式サイト（フロント）
        │
        ▼
Python バックエンド  ·  AWS
  · 会員 / 顧客認証
  · ユーザー ダッシュボード
  · セッション · 接続制御
        │
        ▼
UE5 クライアント（認証済み顧客のみ）
  · 空間の閲覧
  · 素材 · 家具の変更
  · マルチ マテリアル プレビュー
```

顧客を獲得したあと、  
**認証済みアカウントだけ** が UE5 クライアントに入れるようにしました。

### 1アカウント · 1接続

顧客に発行した ID は  
**1 アカウントにつき同時接続 1 か所** だけ許可します。

別 PC（または別セッション）で同じ ID がログインすると、  
先に入っていた側は **自動ログアウト** されます。

ID 共有や多重利用を抑えるためのセッション方針です。

## UE5 クライアントでやったこと

ユーザーが建築インテリア空間の中で  
**素材・家具などを変えながら** 結果をすぐ見られるようにしました。

特に担当したのは次です。

### マルチ マテリアル プレビュー（UI）

UI に素材スウォッチ（サムネイル）を **複数同時に** 並べ、  
カテゴリ（木材 / 大理石 / ソリッド / ファブリック など）· 検索 · デザイン リセットと一緒に  
選んで空間へ反映する流れです。

スウォッチが増えると GPU · メモリ負荷が上がります。  
そのためプレビュー タイルを毎回新規生成せず、  
**オブジェクト プーリング** で再利用しました。

- 画面に必要な枚数だけアクティブ  
- スクロール · フィルタ変更時はプールからスロットを借りて返却  
- テクスチャ · ウィジェット インスタンスの暴走を防ぎ **メモリ · フレーム** を安定化  

ハードウェア メモリとランタイム最適化が肝だった区間です。

### クリックでレベル アクターへ適用

UI でマテリアルを選ぶと、  
プレビューで終わらず、  
**レベル内の該当アクター（壁 · 床 · 家具など）** に実際のマテリアルを適用します。

「選んだもの = 空間に反映されたもの」になるよう、  
UI 選択 → アクター マテリアル セットをつなぎました。

### レンダ · ライティング

- **DLSS** でアップスケールベースの性能確保  
- UE5 内 **ライティング設定の最適化** でインテリア品質とフレームのバランス
